# 协议、行为和验证边界

Sony广播识别厂商0x012D、相机类型03 00。原生NimBLE厂商数据包含两字节厂商ID，不能直接套用Android已剥离ID后的偏移。0x21标签表示电源相关状态，0x22包含配对/遥控标志；广播协议0x65按新定位初始化分支处理，不能仅按相机固件版本推断协议。

连接采用camera-gps-link模式1的主要顺序：建链→请求MTU517→安全过程→非阻塞500ms→服务发现。与Android的系统蓝牙栈不是同一实现，实际MTU、IO协商及重连参数不保证相同。本板提供DisplayYesNo交互能力，启用bonding/MITM/SC，数字比较必须由用户明确确认。

| 服务/特征 | 用途 |
| --- | --- |
| Sony FF00 / 标准base FF01 | 遥控写入；01 09全按、01 08释放、01 07半按、01 06释放半按 |
| FF02 / CCCD 2902 | 状态通知；CCCD写01 00 |
| Sony DD00 / DD11 | GPS定位写入 |
| DD30 / DD31 | 0x65下依次写01锁定和启用定位 |
| DD21 | 定位能力标志 |

GPS包支持91/95字节，大端编码，经纬度×10^7、UTC和可选时区。本版固定+480分钟时区发送95字节；模拟GPS默认关闭，未发送CC13自动校时。模型海拔未作为真实高度发给相机。

RC=1表示本工程发现可用的控制端点，不能仅凭它证明机身蓝牙遥控已启用或相机已落盘。写入确认、快门动作和照片文件是不同验证阶段。间隔计划显示的是完成的命令周期，断线不补拍；120ms遥控脉冲不表示曝光时间。

定位启用失败后本工程会标记GPS不可用并允许可用的遥控继续，未实现App的全部重试。GPS约5秒空闲发送、遥控状态判断、单拍脉冲、单相机保存时机和重连限制也与App存在差异。Android的多相机、后台权限/通知和系统自动校时没有移植。

诊断保留SMP原因、ENC_CHANGE host错误和GAP HCI原因；不要把它们的整数当成同一命名空间。例如host错误7为连接不存在，0x213是HCI base 0x200加远端终止0x13，不能据名称判断有人按了取消。`smp_reason=-1`为未收到配对完成事件。最近12条事件不含MAC、配对码或密钥；运行中的相机名称可能出现在状态文本，分享日志前应自行检查。

NimBLE配对密钥由设备侧协议栈保存，本项目只保存一台相机身份到自己的NVS空间。没有启用Flash加密，不将这些存储说成可抵御物理提取；源码包不包含运行设备上的NVS。
