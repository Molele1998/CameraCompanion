# SD 卡 GPX 记录

0.3.0已实现，真实SD卡、拔插、断电及与相机/动画共存尚待上板。主机检查使用合成定位、SD替身和主机临时文件，不是本板读卡验收。

## 使用

1. 插入可用SD/TF卡，进入桌面「GPS设置 → GPX备份」。当前GPIO4片选与LCD共用SPI，沿用板载插槽，无额外接线。
2. 点「检测SD卡」，成功显示「SD卡已就绪」，才可点「开始GPX备份」。开始时再次重新挂载验证，不把缓存的cardType当作仍插着卡。使用核心支持的FAT文件系统；不会格式化，失败时先保留数据并检查卡。
3. 默认不开启备份，也不自动开启模拟定位。当前没有真实GNSS，若需要测试点，回到GPS首页开启模拟定位；未开启或信号无效时，备份页显示等待数据，文件可以暂时为空轨迹。
4. 回备份页查看点数及文件名。文件保存在卡上 `/CameraCompanion/GPX/SIM_XXXXXX.gpx`，每次新开文件，保留旧轨迹。相机是否连接不影响本地记录。
5. 拔卡前点「停止并保存」，等待停止。返回桌面、停止照片任务、BOOT释放按键均不停止GPX；RESET是重启，不能替代正常保存。

## 格式和数据来源

按[GPX 1.1轨迹结构](https://www.topografix.com/GPX/1/1/)写入标准命名空间、trk/trkseg/trkpt，经纬度、海拔和UTC。输出包含creator；SIM文件元数据写明Synthetic positions/test UTC，而非真实卫星数据。接入真实GNSS的数据源和菜单尚未实现，不能仅改文件名前缀就宣称支持。

当前轨迹为用户要求的模拟GPS，起点/速度/测试时钟与主README一致，不是用户位置。大约1Hz记录，过滤无效数值、无效日期、超过3秒的过期样本及重复/倒退样本；信号中断或两点相隔超过10秒会新开trkseg，避免把失去定位期间画成连续轨迹。

## 存储行为

读写由独立任务执行；LCD和SD外层共用一个SPI互斥锁，各自库仍管理SPI事务。LCD以非阻塞方式尝试锁，存储忙时暂缓屏幕传输，主循环继续触摸和BOOT；慢卡仍可能影响画面刷新，不能把主机通过说成动画帧率已测。

每个点写入后保留XML闭合尾部，并检查fwrite/fflush/fsync；停止关闭文件。它降低正常记录期间出现不闭合XML的概率，但FAT及存储卡缓存并非事务系统，突然掉电或写入中拔卡仍可能需要恢复文件。不要在记录时拔卡。

没有独立卡检测脚的软件实现不会瞬间知道所有拔插；开始前重挂载、读写错误会撤销可用状态并停止记录。重新插卡不会自动恢复，需检测后手动新开文件；不删旧轨迹、不清卡、不影响NVS和相机配对。

## 诊断与验收

USB 115200，新行发送 `status`，新增 `gpx_mounted`、`recording`、`busy`、`points`、`error`、`file`；同一行`frame_ms`为最近整帧处理耗时，包含调度/等待，不能直接当持续FPS。

错误-80表示未挂载/无卡，-81目录创建失败，-82文件名未能避开已存在项，-83文件打开失败，-84写入/同步失败，-85存储任务初始化失败。卡上原有文件均保留。

实测先验证无卡不能开始，再插卡检测、开启模拟GPS并记录一分钟，停止后用地图/GPX软件或XML工具打开文件，核对约1Hz、坐标平滑、日期明确是测试时间。然后验证信号丢失分段、重复开始不覆盖、错误停止、重新插卡不续录，最后与相机遥控和页面动画同时测试。文件有真实GPS数据后不要未经检查放入公开仓库。
